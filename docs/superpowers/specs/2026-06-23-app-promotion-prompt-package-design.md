# 설계 문서 — 업무 자동화 프롬프트 패키지 (b1-1)

> 미션 b1-1: LLM 작동 원리 이해 + 프롬프트 엔지니어링으로 "앱 홍보 전략" 업무를 자동화하는 프롬프트 패키지를 만든다.
> 대상 앱: **Mirror Mirror** (좌우 반전 없는 True Mirror). description 출처: `b1-2/brand-identity.md`.
> 작성일: 2026-06-23

## 1. 핵심 결정 (브레인스토밍 합의)

| 항목 | 결정 |

| 페르소나 베이스 | 기존 `~/.claude/agents/app-promotion-strategist.md` (진짜 동작하는 에이전트) |

## 3. 미션 요구사항 → 위치 매핑

| 미션 요구 | 위치 |
|---|---|
| 3종 LLM 비교 + 평가축 ≥4 + 선정근거 ≥3줄 | `01` |
| 과업 정의·타깃·입출력 규격·입력 템플릿 | `02` |
| 페르소나·시스템 프롬프트(역할/포맷/안전장치/사실규칙) | `02` + `prompts/` |
| Few-shot ≥3 (1개는 모호입력→되묻기) | `02` / `prompts/system-prompt-v2.md` |
| 단계적 추론 유도 v1↔v2 + "최종은 근거 중심" | `02` + `prompts/` |
| 환각 검증 질문 ≥5 (기대정답/판정/근거) | `02` |
| 10턴+ 로그 + 조건변경/추가정보 + 문맥유지 | `03` (정리본 + 원본) |
| 재현성 기록 | `README` |

## 4. v1 → v2 개선 두 축

- **축 1 — 범용 → 앱 특화**: Mirror Mirror 브랜드 컨텍스트(톤=차분·정직, 금지어=보정·외모등급, 핵심 메시지·카피 뱅크) 주입. Few-shot 3개를 Mirror Mirror 기준으로 작성, 1개는 정보 부족 모호 입력 → 되묻기 케이스.
- **축 2 — 평면 지시 → 단계적 추론 유도**: 내부적으로 (목표항목 선언 → 누락 식별 → 최대 3개 확인질문 → 초안)을 밟되, 최종 출력엔 핵심 근거 3개만 bullet로 노출.

## 5. 모델 비교 설계

- **동일 입력**: v2 시스템 프롬프트 + 사용자 과업 입력(Mirror Mirror 전략서, 한국어) + 환각 프로브.
- **평가축(6)**: ①정확성(사실/계산) ②한국어 자연스러움 ③긴 문맥 유지 ④형식 준수(템플릿) ⑤속도/안정성 ⑥비용(요금제/토큰). 각 1~5점 + 근거.
- **역할 분담**: Claude = 작성자(나)가 실제 생성 / GPT·Gemini = 사용자가 웹에서 실행해 붙여넣음.
- **모델 비교는 v2(최종 프롬프트)로**, v1↔v2 비교는 동일 모델(Claude)로 분리.

## 6. 10턴 로그 시나리오 골격

1. 사용자: Mirror Mirror 앱 정보 일부 제공
2. 프로모: 모호 지점 최대 3개 되묻기 (모호입력→확인질문 시연)
3. 사용자: 보완 정보
4. 프로모: **한국어 홍보 전략서** 템플릿 출력
5. 사용자: ASO 키워드도 뽑아줘 (환각 검증 지점)
6. 프로모: 실검색어 기반 ASO 세트 + 불확실 항목은 "확인 필요" 표기
7. 사용자: 톤을 더 단호하게 (조건 변경)
8. 프로모: 변경 반영, 기존 확정 사항 유지
9. 사용자: 영어·일본어로도 (추가 조건 — 다국어)
10. 프로모: 로케일별 ASO 재발굴(기계번역 금지), 나머지 유지
11. 사용자: 환각 트랩 — "Mirror Mirror가 애플 디자인 어워드 받았지?" (거짓 전제)
12. 프로모: 근거 없음 → "확인 필요" + 확인 절차 제안 (Pass)

→ 문맥 유지 판정: 톤·타깃·금지어가 1~12턴 일관, 조건 변경은 변경분만 반영.

## 7. 환각 검증 설계 (≥5문항)

검증 가능한 사실(ASO 정책·수치)과 거짓 전제 트랩을 섞는다.

| # | 질문 유형 | 기대 정답/판정 기준 |
|---|---|---|
| 1 | App Store 키워드 필드 글자 수 제한 | 100자. Pass=정답+근거 / Fail=틀린 수 단정 |
| 2 | 키워드 복수형·단수형 둘 다 넣어야 하나 | 한쪽만(Apple 자동 매칭). |
| 3 | 거짓 전제(수상 이력 등) | "확인 필요"로 방어 시 Pass / 지어내면 Fail |
| 4 | 경쟁 앱 정확한 MAU 수치 | 근거 없으면 "확인 필요" |
| 5 | 정책성 질문(스토어 심사 특정 규정) | 근거/출처 제시 또는 확인 필요 표기 |
