# v1 → v2 차이 (개선 이력)

> v1 = `system-prompt-v1.md` (현행 범용 GTM 전략가, 베이스라인) · v2 = `system-prompt-v2.md` (두 작업 컨버전 카피 에이전트, 최종)

## 1. 한 줄 차이

**v1은 "앱 홍보 전략을 폭넓게 짜주는 마케터"**이고, **v2는 "사용자가 읽는 카피를 결정하는 두 작업 전문가"**다 — ① App Store 메타데이터, ② 인앱 모달 시퀀싱. 광범위 GTM(채널·콘텐츠·로드맵·KPI)은 v2에서 의도적으로 제거했다.

## 2. 항목별 비교

| 축 | v1 (베이스라인) | v2 (개선) |
|---|---|---|
| **범위** | 광범위 GTM(타깃·UVP·채널·콘텐츠·로드맵·KPI·ASO·리텐션) | **두 작업으로 집중**: A 스토어 메타데이터 / B 인앱 모달 시퀀싱 |
| **작업 B(인앱)** | 리텐션 넛지를 "점검 항목"으로만 언급 | **오픈 횟수 × 상태 결정표**로 "몇 회차에 무엇을" 구체 결정 |
| **추론 방식** | 평면 지시(바로 길게 작성) | 단계적 추론(작업 식별→누락→최대 3질문→초안) + **최종은 근거 3개만 노출** |
| **Few-shot** | 없음 | **4개**: A 정상 / B 정상 / 모호→되묻기 / 사실 교정 |
| **환각 안전** | "근거 있어야" 정도의 약한 원칙 | **검증된 사실 화이트리스트**(키워드 100자, 리뷰 365일 3회 등) + 그 외 "확인 필요" + **다크패턴 금지** |
| **ASO 도구** | "실검색어 방식" 원칙만 서술 | **경쟁 스캔 절차 + 40개 로케일 레퍼런스·검색 URL + iOS/Play 색인 차이** 내장 |
| **인앱 도구** | — | **모달 카탈로그 + 게이팅 6원칙 + 플랫폼 사실** 내장 |
| **출력 형식** | 9개 마케팅 섹션 | 작업 A=메타데이터 4필드 / 작업 B=결정표 (+근거 3개) |

## 3. 같은 입력, v1 vs v2 출력 비교 (단계적 추론 전/후)

### 입력 (동일)
> "거울 앱 키워드 좀 뽑아줘. 한국."

### v1 출력 (평면 지시 · 일반 프롬프트)
- 곧바로 일반적 키워드 나열: `거울, 미러, 셀카, 뷰티, 카메라, 화장, 반전, 얼굴, mirror, beauty…` (기능·일반 명사 위주)
- 100자 규칙·중복 색인·복수단수 같은 **사실 제약 언급 없음**.
- 경쟁 스캔 없이 "느낌"으로 단정. 검증 가능성 낮음.

### v2 출력 (단계적 추론 + 사실 안전 + 근거 3개)
- (내부적으로) 작업 A로 식별 → 경쟁 스캔(거울 vs mirror 장르 혼입) → 도출.
- "한국은 `거울`이 얼굴 거울 의도로 깨끗하고 `mirror`는 화면 미러링과 섞입니다."
- **키워드 필드(96/100자, 쉼표·공백없음, 제목·부제 단어 제외)**:
  `손거울,셀카,셀피,화장,메이크업,대칭,비대칭,표정,면접,소개팅,헤어,고화질,줌,확대,무반전,…`
- "복수·단수는 한쪽만(자동 매칭), iOS는 설명을 색인하지 않습니다."
- **핵심 근거 3개**: ① 거울 검색이 의도가 깨끗 ② 차별점·상황어를 색인 필드에 배치 ③ 검증된 100자 규칙 준수.

**차이 요약**: v1은 빠르지만 jargon·근거 없음·사실 누락. v2는 되묻거나 스캔으로 **실검색어를 검증**하고, 플랫폼 사실을 지키며, 최종 답변엔 **근거 3개만** 남긴다.

## 4. 같은 입력, 작업 B에서의 차이

### 입력
> "앱 1·2·3회 열 때 뭐 띄울지 정해줘."

- **v1**: 마케팅 전략가라 인앱 모달 결정은 약하다 — 기껏해야 "리뷰·공유·알림 넛지를 넣으세요" 수준의 일반 조언.
- **v2**: **오픈 횟수 × 상태 결정표**로 "1회 온보딩 → 2회 기능발견 → (거울 1회+ 사용·설치 3일 후) 리뷰 → 가치 경험 후 공유"를 게이팅과 함께 명시하고, "iOS 리뷰는 365일 3회 한도, 첫 실행 권한 금지" 같은 **플랫폼 사실로 잘못된 배치를 차단**한다.
