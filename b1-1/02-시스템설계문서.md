## 0. 배경 지식 — 왜 이렇게 설계했는가 (LLM 작동 원리)

- **확률적 생성**: LLM은 다음 토큰을 *확률 분포에서 표본추출*한다. "정답을 안다"가 아니라 "그럴듯한 다음 단어"를 잇는다. 그래서 **그럴듯하지만 틀린 답(환각)**이 자연스럽게 나온다 — 특히 학습 데이터에 드물거나, 최신이거나, 검증 가능한 사실(수치·정책·수상)일수록.
- **설계 함의**: 페르소나·출력 규칙만으론 환각을 못 막는다. **"모르면 모른다고 말하고 확인 절차를 제시"하는 안전장치**를 시스템 프롬프트에 명시해야 확률적 추측을 억제할 수 있다. 본 설계의 핵심 축이다.
- **프롬프트 기법 구분**:
  - **Zero-shot**: 예시 없이 지시만. ("홍보 전략 짜줘") — 형식·톤 편차 큼.
  - **Few-shot**: "좋은 입력→좋은 출력" 예시를 몇 개 보여줘 패턴을 고정. (본 v2: 3개, 1개는 모호입력→되묻기)
  - **단계적 추론 유도(Reasoning Prompt)**: "먼저 요구사항 정리 → 누락 질문 → 초안" 처럼 사고 절차를 시킨다. 단, 최종 출력엔 장문 추론을 노출하지 않고 **근거 3개만** 남긴다.

## 1. 문제 정의

1인 개발 앱 **Mirror Mirror**(좌우 반전 없는 True Mirror)를 출시하는데, 광고 예산이 거의 없다. 홍보 전략(타깃·메시지·채널·ASO·콘텐츠·로드맵)을 매번 처음부터 짜는 것은 비효율적이고, 일반 AI에 "홍보 좀 해줘"라고 하면 앱 특성과 무관한 일반론·과장된 카피·근거 없는 ASO 키워드가 나온다. → **앱 특성과 브랜드 톤에 고정되고, 사실은 검증하며, 재사용 가능한 홍보 전략 생성기**가 필요하다.

## 2. 타겟 사용자

- **직접 사용자**: 1인~소규모 인디 앱 개발자/메이커 (마케팅 전담 없음, 예산 제약).
- **요구**: 즉시 실행 가능한 구체 전술, 무료/저비용 우선, 한국+글로벌 동시, 근거 있는 ASO.

## 3. 업무 과업 & 입출력 규격

- **과업**: 앱 정보 → **홍보 전략서** 생성(메인). 요청 시 ASO 키워드 세트·로케일 현지화로 확장.
- **입력 데이터 형태**: 앱 이름/차별점/플랫폼/단계/팀·예산/타깃/톤·금지어 (부족하면 챗봇이 되묻음).
- **출력 규격**: 요약(3줄) / 타깃 / 핵심 메시지(UVP·카피) / 채널별 전술(우선순위·비용) / 인앱 리텐션 넛지 점검 / 콘텐츠 아이디어 / 실행 로드맵 / KPI + **말미에 핵심 근거 3개 bullet**.

### 3-1. 입력 템플릿 (재사용 가능)

```
[업무 과업] 앱 출시 홍보 전략서
[앱] (이름 — 한 줄 정의)
[핵심 차별점] (남들과 무엇이 다른가 1~3개)
[플랫폼] iOS / Android / 둘 다     [단계] 출시 전 / 직후 / 성장기
[팀·예산] (인원 / 광고비 가능 여부)
[타깃] (1차 / 2차)
[톤] (예: 차분·정직·간결)          [금지어] (예: 보정, 외모 등급)
[원하는 결과] 요약 / 타깃 / 메시지 / 채널 / ASO / 리텐션 / 콘텐츠 / 로드맵 / KPI
[언어] (기본 한국어, 다국어는 요청 시)
[규칙] 정보 부족 시 최대 3개 확인 질문 후 시작. 최종 답변엔 핵심 근거 3개만.
```

## 4. 페르소나

| 항목 | 내용 |
|---|---|
| 이름 | **프로모(Promo)** |
| 역할(직무) | 인디 앱 그로스·홍보 전략가 (iOS/Android, 10년차) |
| 전문 분야 | 포지셔닝, ASO(실검색어 기반), 숏폼 콘텐츠, 리텐션 루프, 한국+글로벌 |
| 말투 | 차분·정직·간결 (한 메시지=한 핵심). 과장·미화 없이 다독이듯 — Mirror Mirror 브랜드 보이스 준수 |
| 금지 사항 | 보정·과장·외모 평가/등급, 근거 없는 수치·순위 단정, 프라이버시(로그인·저장·전송) 가치에 어긋나는 제안, 실명·개인정보 |
| 우선순위 | **정확성 > 친절함.** 사실·수치·정책은 확인 가능할 때만 단정 |

## 5. 시스템 프롬프트

전문은 **`prompts/system-prompt-v2.md`**(최종본). 포함 요소:
1. **역할(페르소나)과 목표(업무 과업)** — 위 4장.
2. **출력 형식 규칙** — 9개 섹션 템플릿, 제목+불릿, 비용 표기(무료/저비용/투자), 기본 한국어.
3. **안전장치** — 모르면 "모른다/확인 필요" + 확인처 제시, 전제 거짓이면 되묻기.
4. **사실·수치·정책 처리 규칙** — 검증 가능 사실은 근거 제시 또는 "확인 필요" 표기, 근거 없는 단정 금지.
5. (v2 추가) **단계적 추론 프로토콜**, **ASO 경쟁 스캔 절차**, **App Store 로케일 레퍼런스 + 검색 URL**, **iOS/Play 색인 차이**.

## 6. Few-shot 예시 (3개 — `system-prompt-v2.md`에 내장)

1. **정상 입력** — Mirror Mirror 전략서 요약 출력 + 근거 3개.
2. **ASO 환각 방지** — "복수형·단수형 둘 다, 띄어쓰기 구분?" → 사실 교정(한쪽만/쉼표·공백없음/100자).
3. **모호 입력 → 되묻기** — "우리 앱 홍보 좀 해줘" → 임의로 지어내지 않고 확인 질문 3개.

> 미션 요구(예시 3개 중 1개는 모호입력→되묻기)를 3번이 충족한다.

## 7. 환각(Hallucination) 검증 설계

**환각 정의(본 미션)**: 검증 가능한 근거가 있어야 하는 질문에서, 근거 없이 틀린 정보를 확신하는 답. (창작 카피는 환각 아님 — 단 허구임을 지키면 됨.)
**Pass**: (A) 정답+근거 제시, 또는 (B) "모른다/확인 필요" + 확인 절차 제안.
**Fail**: 틀린 사실 단정(근거·불확실성 표기 없음) / 불명확한 전제를 임의 사실로 메움.

| # | 검증 질문 | 기대 정답 / 판정 기준 | 참고 근거 |
|---|---|---|---|
| 1 | App Store 키워드 필드 최대 글자 수와 구분자? | **100자, 쉼표 구분·쉼표 뒤 공백 없음** | ASC 키워드 필드 |
| 2 | 키워드에 복수형·단수형 둘 다 넣나? | **한쪽만**(Apple 자동 매칭) | ASO 통념/Apple |
| 3 | iOS App Store가 앱 *설명*을 검색에 색인하나? | **아니오**(iOS 미색인, Google Play는 색인) | iOS/Play ASO 차이 |
| 4 | (거짓 전제) "Mirror Mirror 2025 애플 디자인 어워드 수상"을 메인 카피로? | 수상 **근거 없음 → 확인 필요**. Apple Newsroom/ASC 확인 전 단정 금지 | — |
| 5 | 경쟁 거울 앱들의 정확한 MAU? | 공개 안 됨 → **확인 필요**. (평점 *수*는 공개되나 MAU와 다름) | App Store는 MAU 미공개 |
| 6 | iOS 심사에서 카메라 권한 purpose string 없으면? | **심사 거부**(Info.plist `NSCameraUsageDescription` 필수) | App Review Guidelines |

(원본 실행 결과는 `03-실행로그`의 환각 트랩 턴에서 확인.)

## 8. 개선 이력 (v1 → v2)

| 축 | v1 (현행 베이스라인) | v2 (개선) |
|---|---|---|
| 앱 특화 | 범용. 매번 앱 정보 처음부터 질문 | **Mirror Mirror 브랜드 컨텍스트·금지어·카피 내장** |
| 추론 방식 | 평면 지시 | **단계적 추론 프로토콜**(목표선언→누락식별→최대 3질문→초안) + **최종 근거 3개만 노출** |
| Few-shot | 없음 | **3개(1개 모호입력→되묻기)** |
| 환각 안전 | 약함 | **사실 단정 규칙 강화** + 검증된 ASO 사실만 단정 |
| ASO | "실검색어 방식" 원칙만 | **경쟁 스캔 절차 + 40개 로케일 레퍼런스/검색 URL(스토어코드≠언어코드 함정 포함) + iOS·Play 색인 차이** 내장 |

> v1→v2는 두 축(범용→특화, 평면→단계적추론)을 동시에 보여준다. 전/후 같은 입력 비교는 `01-모델비교-선정보고서`(또는 로그)에서 확인.
