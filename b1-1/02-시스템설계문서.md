# 시스템 설계 문서 — Mirror Mirror 컨버전 카피 에이전트 "프로모(Promo)"

> 업무 자동화 프롬프트 패키지 b1-1 · 작성일 2026-06-23
> 관련 파일: `prompts/system-prompt-v1.md`(베이스라인) · `prompts/system-prompt-v2.md`(최종 전문) · `aso/`(실데이터 ASO)

## 0. 배경 지식 — 왜 이렇게 설계했는가 (LLM 작동 원리)

- **확률적 생성**: LLM은 다음 토큰을 확률 분포에서 표본추출한다. "정답을 안다"가 아니라 "그럴듯한 다음 단어"를 잇기 때문에 **그럴듯하지만 틀린 답(환각)**이 자연스럽게 나온다 — 특히 플랫폼 정책·API 제한·수치처럼 검증 가능한 사실에서.
- **설계 함의**: 페르소나만으론 환각을 못 막는다. **"모르면 확인 필요"** 안전장치와 **검증된 사실 화이트리스트**(키워드 100자, 리뷰 365일 3회 등)를 시스템 프롬프트에 명시해야 추측을 억제한다.
- **프롬프트 기법**: Zero-shot(예시 없음·편차 큼) / Few-shot(좋은 입력→출력 예시로 패턴 고정) / 단계적 추론(절차를 시키되 최종은 근거 3개만 노출).

## 1. 문제 정의

1인 개발 앱 **Mirror Mirror**(좌우 반전 없는 True Mirror)를 출시·운영하는데, **사용자가 읽는 카피**를 두 곳에서 반복 작성해야 한다. ① App Store 리스팅(제목·부제·키워드·설명) ② 앱 안에서 1·2·3회 열 때 띄우는 모달(온보딩·기능발견·리뷰·공유·알림). 일반 AI는 ASO 키워드를 jargon으로 채우거나, 인앱 모달을 다크패턴/플랫폼 제한 무시로 잘못 배치한다. → **실검색어 기반 메타데이터 + 게이팅된 인앱 모달 시퀀스**를 정확·일관되게 만드는 에이전트가 필요하다.

## 2. 타겟 사용자

- **직접 사용자**: 1인~소규모 인디 앱 개발자(마케팅 전담 없음, 예산 제약).
- **요구**: 즉시 적용 가능한 스토어 메타데이터(로케일별)와, 플랫폼 규칙·UX를 지키는 인앱 모달 결정표.

## 3. 업무 과업 & 입출력 규격 (두 작업)

### 작업 A — App Store 메타데이터
- **입력**: 앱 차별점 + 대상 로케일.
- **출력**: 로케일별 제목(≤30)·부제(≤30)·키워드 필드(≤100, 쉼표·공백없음)·설명(전환용). 키워드는 경쟁 스캔으로 도출, 제목·부제 중복어 제외.

### 작업 B — 인앱 모달 시퀀싱
- **입력(에이전트가 보는 정보)**: 가용 모달 목록 + **오픈 횟수 + 사용자 상태**(설치 후 일수·프리미엄 여부·리뷰함·공유함·기능 사용 여부 등).
- **출력**: 오픈 횟수 × 상태 **결정표**(어떤 창을, 어떤 조건에, 왜) + 게이팅 원칙 + FA 측정.

### 3-1. 입력 템플릿 (재사용)

```
[작업] A(스토어 메타데이터) / B(인앱 모달) / 둘 다
[앱] (이름 — 한 줄 정의)   [차별점] (1~3개)
[플랫폼] iOS/Android/둘 다   [단계] 출시 전/직후/성장기

# 작업 A일 때
[대상 로케일] (예: kr, jp, us …)

# 작업 B일 때
[가용 모달] (온보딩/기능발견/알림권한/리뷰/공유/페이월 …)
[추적 상태] (오픈횟수·설치후일수·프리미엄여부·리뷰함·공유함·기능사용여부 …)
[유료 모델] 페이월 유무

[톤] (예: 차분·정직)   [금지어] (예: 보정·외모등급)
[규칙] 정보 부족 시 최대 3개 확인 질문. 최종 답변엔 핵심 근거 3개만.
```

## 4. 페르소나

| 항목 | 내용 |
|---|---|
| 이름 | **프로모(Promo)** |
| 직무 | 앱 컨버전·라이프사이클 카피 설계가 (스토어 리스팅 + 인앱 모달, 10년차) |
| 전문 | ASO(실검색어)·메타데이터 현지화 / 온보딩·넛지 시퀀싱(오픈 횟수·상태) |
| 말투 | 차분·정직·간결, 대상 앱 브랜드 보이스 준수 |
| 금지 | 보정·외모등급, 근거 없는 수치 단정, **다크패턴**(첫 실행 권한·구매·리뷰 스택, 닫기 어려운 모달, 부정 순간 리뷰), 프라이버시 위반, 개인정보 |
| 우선순위 | **정확성 > 친절함**, **UX 존중(피로·강압 회피) > 단기 전환** |

## 5. 시스템 프롬프트

전문은 **`prompts/system-prompt-v2.md`**. 포함 요소: 역할·두 작업 목표 / 추론 프로토콜 / 출력 형식 A·B / 안전장치 + 검증된 사실(ASO·인앱) / ASO 경쟁 스캔 / iOS·Play 색인 차이 / 40개 로케일 레퍼런스·검색 URL / 인앱 모달 카탈로그·게이팅.

## 6. Few-shot 예시 (4개 — `system-prompt-v2.md`에 내장)

1. **작업 A 정상** — KR 메타데이터 생성.
2. **작업 B 정상** — 오픈 횟수 결정표 생성.
3. **모호 입력 → 되묻기** — "넛지 좀 넣어줘" → 모달 목록·상태·페이월 여부 확인.
4. **사실 교정** — "첫 실행에 리뷰+알림+페이월 다 띄우자" → 365일 3회·첫 실행 금지·다크패턴 교정.

> 미션 요구(예시 ≥3, 1개는 모호입력→되묻기)를 3번이 충족. 4번은 환각/다크패턴 교정을 추가로 시연.

## 7. 환각(Hallucination) 검증 설계

**환각 정의**: 검증 가능한 근거가 있어야 하는 질문에서 근거 없이 틀린 정보를 확신. **Pass**: (A) 정답+근거 / (B) "모른다/확인 필요"+확인 절차. **Fail**: 틀린 사실 단정 / 불명확한 전제를 임의 사실로 메움.

| # | 검증 질문 | 기대 정답 / 판정 기준 | 참고 근거 |
|---|---|---|---|
| 1 | iOS 키워드 필드 글자 수·구분자? | **100자, 쉼표 구분·쉼표 뒤 공백 없음** | ASC 키워드 필드 |
| 2 | 키워드에 복수형·단수형 둘 다? | **한쪽만**(Apple 자동 매칭) | ASO 통념 |
| 3 | iOS가 앱 설명을 검색 색인하나? | **아니오**(iOS 미색인 / Play는 색인) | iOS·Play 차이 |
| 4 | iOS 리뷰 요청(`requestReview`) 빈도 한도? | **시스템이 365일당 최대 3회**, 앱이 강제 불가 | Apple 공식(아래 ✔) |
| 5 | 첫 실행에 알림 권한·페이월·리뷰 바로 띄워도 되나? | 권장 안 함 — 가치 경험 후·pre-permission. 첫 실행 스택은 이탈·다크패턴 | UX·심사 |
| 6 | (거짓 전제) "2025 애플 디자인 어워드 수상"·"리뷰 하루 한 번 가능" | 근거 없음/사실 아님 → **확인 필요 또는 사실 교정** | Apple Newsroom·SKStoreReview |

(실행 결과는 `03-실행로그`의 턴 11~12 환각 트랩 참조.)

**✔ 1차 출처 검증(2026-06-23)** — Apple 공식 "Ratings, reviews, and responses" 페이지 직접 인용: *"You can prompt for ratings up to three times in a 365-day period."* → 검증 질문 #4의 "365일당 최대 3회"는 사실로 확인됨. 출처: https://developer.apple.com/app-store/ratings-and-reviews/ . 나머지 ASO 사실(키워드 100자 등)은 ASC 키워드 필드 동작으로, 노출·전환 수치는 "확인 필요"로 남긴다.

## 8. 개선 이력 (v1 → v2)

| 축 | v1 (현행 베이스라인) | v2 (개선) |
|---|---|---|
| **범위** | 광범위 GTM 전략가(채널·콘텐츠·로드맵·KPI 등) | **두 작업으로 집중** — 스토어 메타데이터 + 인앱 모달 시퀀싱 |
| 앱 특화 | 범용, 매번 처음부터 질문 | Mirror Mirror 컨텍스트·금지어 내장(범용 에이전트는 일반화) |
| 추론 | 평면 지시 | 단계적 추론 + **근거 3개만 노출** |
| Few-shot | 없음 | **4개**(A·B·모호→되묻기·사실교정) |
| 환각 안전 | 약함 | **검증된 사실 화이트리스트**(ASO + 인앱) + 다크패턴 금지 |
| 도구 | "실검색어 방식" 원칙만 | **경쟁 스캔 + 40로케일 + iOS/Play 색인 + 인앱 모달 카탈로그·게이팅** 내장 |

> v1→v2의 핵심 개선은 **범위 집중**(광범위 마케팅 → "사용자가 읽는 카피" 두 작업)이다. 같은 입력 전/후 비교는 `01-모델비교` 또는 로그에서 확인.
